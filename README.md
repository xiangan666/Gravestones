## 功能

| 功能 | 行为 |
| --- | --- |
| 完整中文界面 | 墓碑、钥匙、寻墓器、菜单、状态提示、物品说明均为中文；英文语言环境也显示中文 |
| 唯一墓碑编号 | 每次死亡独立生成，支持多座同时存在；持久化递增编号；放置时悬浮显示 `#编号 玩家名的墓碑`；所有者读取实际死亡玩家名，钥匙、墓碑物品与寻墓器使用相同编号 |
| 经验保存 | 保存死亡时的**总经验点数**；首次开启时所有者获得70%，其他玩家获得50%，向下取整；每座墓碑只结算一次 |
| 完整遗物 | 保存背包、头盔、胸甲、护腿、靴子和副手；使用原生 ItemStack 容器迁移，保留附魔、耐久、名称、说明及其他模组动态属性；空背包零经验也生成独立墓碑 |
| 完整物品说明 | 墓碑编号、所有者、原始维度和坐标、死亡坐标、保存经验、物品种类、堆数和总数量 |
| 搬运墓碑 | 挖掘后生成可拾取的墓碑实体，拾取后可以再次放置；携带对应编号钥匙开启 |
| 掉落保护 | 墓碑物品包含防火组件；独立掉落实体免疫伤害、不设置消失计时器；岩浆中浮至液面上方，爆炸不会摧毁墓碑方块 |
| 钥匙菜单 | 手持钥匙使用：基本信息、传送至墓碑、合成寻墓器 |
| 一次性传送 | 每把钥匙一次；确认并成功传送消耗1个末影珍珠；传送后钥匙保留，可继续开墓，全部领取后消耗；失败不扣次数、退还已扣珍珠 |
| 开墓消耗钥匙 | 遗物全部领取成功后，仅消耗当前实际使用的1把对应编号普通钥匙；管理员钥匙、其他墓碑钥匙及未使用的副本不受影响 |
| 原始位置限制 | 墓碑必须从未被挖起且仍在初次生成位置；即使挖起后放回原位置，也不能传送 |
| 未加载区块 | 使用持久化状态判断资格；临时加载目标并验证安全落脚点，加载失败不报“已挖起/数据丢失”、不扣费 |
| 附近安全传送 | 搜索水平32格、上下32格的安全地面，识别草丛；没有天然落点时，在附近空旷处搭建3×3圆石落脚台，成功后保留；不强行传入岩浆或实体方块 |
| 寻墓器 | 绑定钥匙 + 指南针合成；16方向动态针尖，跟随放置、掉落、玩家背包及已记录容器中的墓碑 |
| 补领钥匙 | 所有者手持末影珍珠使用放置中的墓碑，合计扣除20个末影珍珠，获得对应编号的新钥匙 |
| 满背包保护 | 不能放入背包的遗物仍留在墓碑中，保留钥匙供续领；最后一次领完才消耗，经验不重复发放 |
| 旧版迁移 | 加载旧版墓碑时迁移库存并分配编号；所有者可用原始坐标钥匙使用旧墓碑，升级为新绑定钥匙 |

### 经验规则示例

死亡时总经验为101点，所有者首次开启返还70点，其他玩家首次开启返还50点。未返还部分消散。经验按点数计算，**不是等级的70%或50%**。旧版已经生成经验球的经验无法追溯，旧墓碑迁移经验记为0。

### 寻墓器合成方式

1. 手持需要追踪的**绑定墓碑钥匙**，对空气使用以打开菜单。
2. 背包准备1个普通指南针。
3. 选择“合成寻墓器”，确认后消耗这把钥匙和1个指南针，原位置生成对应编号寻墓器。

这是带绑定数据的**菜单合成**，不是工作台配方。原生配方无法可靠继承所消耗钥匙的动态属性，菜单合成可以保证多个墓碑之间不串绑。寻墓器不能代替钥匙开墓；需要时用20个末影珍珠补领钥匙。移除了原版空白钥匙配方，避免无效钥匙混淆。

手持寻墓器时，红色针尖相对于玩家朝向旋转，动作栏显示维度、坐标、状态和水平距离。跨维度时提示前往目标维度；目标在离线玩家身上或未加载区块时，显示最后持久化位置。已开启的墓碑显示最后位置及“已开启”，不伪装成仍可领取。容器追踪及管理命令边界见 [实现说明](docs/DESIGN.md)。

## 安装

1. 从[GitHub Releases](https://github.com/xiangan666/Gravestones/releases)下载 `Gravestones-lanshiyi-v2.0.14.mcaddon` 及同名 `.sha256` 校验文件，核对摘要后打开安装。也可在源码目录执行 `npm run build`，取得 `dist/` 中的同名产物。一个安装包包含行为包、资源包、安装与归属说明；构建保留历史版本文件。
2. 双击/打开 `.mcaddon` 导入 Minecraft 基岩版。
3. 在世界设置中同时启用“墓碑模组 2.0.14”的**行为包和资源包**。升级时替换原包，避免同时运行两套墓碑脚本。
4. 允许命令/作弊，供旧保险库恢复及远距离传送按需创建常加载区域；预留恢复和传送所需的区域配额。保险库通过一个共享的原生常加载锚点维持实体加载，不为每座墓碑单独创建锚点。
5. 进入世界查看内容日志，确认没有包依赖或脚本报错，随后在测试世界死亡验证。

本模组延续原版方案，自动开启并维护 `keepInventory=true`，然后自行把遗物转入墓碑。已有绑定钥匙、寻墓器及可搬运墓碑留在玩家身上，避免遗物形成循环嵌套。即使只带钥匙且零经验，再次死亡也会创建新编号墓碑，已有墓碑继续保留。保险库创建失败或附近无可用位置时，保留物品与经验并提示；不会故意删掉玩家遗物。不要与同时接管死亡背包的其他模组共用。

### 从2.0.9 / 2.0.10 / 2.0.11 / 2.0.12 / 2.0.13升级

先备份世界，再导入2.0.14并确认世界启用了新版本的两包。包UUID保持不变，已有墓碑、钥匙与编号沿用；同一座墓碑挖起、再次放置保留编号，新死亡生成的新墓碑才递增编号。

2.0.12起，全部领取墓碑遗物后自动消耗本次使用的普通绑定钥匙，旧版已有钥匙同样适用，无需重新生成。背包满、部分领取、错误钥匙或库存加载失败都不会提前消耗。其他未使用的钥匙不会被全局清理；已开启墓碑不能再次领取或传送。

2.0.11在真实引擎中确认：旧版实体使用的`deals_damage: false`在当前实体格式中被判无效，埋在基岩中的库存实体及常加载锚点会窒息死亡。现已改为有效的字符串枚举`"no"`，并修正浮力参数范围。旧版“加载好了仍找不到库存”的问题不能只靠增加等待修复。

**如果旧库存实体已经在旧版本中死亡/被删除，更新安装包不能凭编号和物品数量重建原有物品数据。** 仍存在的库存可以继续使用；已损失的遗物需从出问题之前的世界备份恢复。开墓仍会等待加载、按编号重连，缺失时保留墓碑和经验记录，不创建空库存、不伪报领取成功。

## 使用

- **生成**：玩家死亡后生成墓碑；复活后自动发放绑定钥匙。背包无空位时暂存待发钥匙，腾出空位后自动补发。
- **开墓**：手持相同编号钥匙，对放置的墓碑使用；全部领取成功后消耗本次使用的1把钥匙，未领完则保留供续领。持有钥匙的其他玩家也可开启，按50%返还经验，领完同样消耗。
- **查看/传送**：手持钥匙对空气使用。传送需要背包中有1个末影珍珠。优先送到附近安全地面；确无天然落点时，在空旷处搭建小落脚台。确认界面会说明此行为；空间不足或加载失败不扣费。
- **搬运**：正常挖掘墓碑；靠近掉落实体拾取。手持墓碑物品，对着有空位的方块表面使用以放置。
- **补钥匙**：所有者手持末影珍珠使用墓碑。20颗珍珠从整个背包跨堆合计扣除；不足时不会部分扣费。新钥匙也受“从未移动”的传送限制。
- **管理员**：保留原版管理员钥匙及其昂贵配方，管理员钥匙开启后不消耗。具有 `admin` 标签的玩家也可取出遗物，不会误删其手持的其他墓碑钥匙；若使用匹配的普通钥匙则正常消耗，经验仍按是否所有者决定比例。

## 本地开发

需要 Node.js 24+、npm 11+、Python 3.10+；CI使用Node.js 24和Python 3.12，在Windows与Linux上校验。日常检查与打包不依赖 Pillow；重新生成像素图标时才需要 `python -m pip install pillow`。

```powershell
npm ci
npm run check
npm test
npm run build
npm run build:verify
```

源码结构：

```text
Grave_B/                 行为包：方块、物品、持久实体和脚本
Grave_R/                 资源包：模型、纹理、中文语言文件
tests/                   经验/状态单元测试与模拟运行集成测试
tools/validate.py        JSON、依赖、UUID、汉化与保护组件检查
tools/build.py           可重复构建、校验文件和源码逐项核对
tools/sync_version.py    清单、包与脚本版本同步
tools/check_docs.py      本地文档链接检查
tools/release.py         标签、草稿资产、正式发布及下载核对
tools/prepare_assets.py  生成元数据、物品定义和像素图标
tools/run_native_tests.py 官方Windows BDS双会话原生回归（需自行提供官方服务端ZIP）
docs/                    架构、验收及 GitHub 发布说明
.github/                 问题模板、CI 和标签发布流程
```
