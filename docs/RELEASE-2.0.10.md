# 墓碑模组 2.0.10 · 多墓碑与开墓修复

原作 Effect99。汉化与二改 lanshiyi，联系 3199912548@qq.com。

本版修复2.0.9中“看起来一直只有#1墓碑”和“钥匙识别成功但打不开库存”的相关问题：

- 仅保留钥匙且经验为零时，再次死亡也会创建独立墓碑，多座同时保留。
- 编号从主/备用计数及已有记录恢复，防止计数回退时重用已存在的编号；记录保存增加冲突保护。
- 已加载库存直接读取；未就绪时等待实体加载，旧实体ID失效时按墓碑编号恢复唯一关联。
- 使用共享常加载锚点维护保险库，开墓过程加锁并重新核对钥匙。
- 库存确实缺失时保留记录并明确提示，不创建空库存掩盖遗物丢失。

墓碑标题读取实际死亡玩家名，格式为`#编号 玩家名的墓碑`，不会固定显示作者名。同一座墓碑挖起、放回后仍保留原编号，只有新死亡生成的新墓碑获得新编号。

升级前备份世界。导入`Gravestones-lanshiyi-v2.0.10.mcaddon`，确认世界启用新版行为包和资源包；UUID保持不变，兼容2.0.9的已有墓碑及钥匙。仅凭安装包无法恢复已经被外部删除或覆盖的物品库存。

基岩版目标最低版本1.21.90，稳定Script API 2.0.0。旧库存恢复和远距离传送仍需命令权限及常加载区域配额。交付保持一个`.mcaddon`文件，SHA-256仅输出到构建日志。
