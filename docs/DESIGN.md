# 实现说明

| 文件 | 职责 |

## 状态与编号

`placed → dropped → carried → placed`，开墓后终止为 `opened`。首次挖掘同时永久设置 `everMoved=true`。重新放置、补发钥匙及返回原始坐标都不会重置这个标志。

每次死亡独立创建一座墓碑，即使只有保留的钥匙且背包零遗物、零经验，也不会跳过。同一墓碑挖起、重新放置沿用编号，不会因此分配新编号。墓碑所有者读取实际死亡玩家的`player.name`，lanshiyi只用于作者署名。

世界动态属性 `lanshiyi:grave_sequence` 与备用`grave_sequence_high_water`保存编号上限；启动和分配时结合已有墓碑记录、已加载库存/显示/掉落实体、玩家所持绑定物品恢复最高编号。计数缺失或回退不能覆盖已有墓碑；分配失败允许跳号，已使用编号不重用。每个墓碑独立保存 `lanshiyi:g:<编号>` JSON，包含所有者、原始位置、死亡位置、当前位置、状态、曾移动标志、库存实体ID/坐标、显示/掉落实体ID、经验、统计和结算状态。记录保存拒绝覆盖所有者或创建时间不同的同编号记录。

物品以数值动态属性 `lanshiyi:grave_id` 绑定；显示名称与说明用于展示，不作为权限凭据。所有者身份使用玩家实体持久ID，避免单靠显示名认领。

## 物品持久化

42格 `lanshiyi:grave_storage` 原生库存实体位于主世界单一保险库区块：背包使用0–35，护甲与副手使用36–40。位置由第一次启动时世界出生点所在区块决定，高度为世界最低高度+4，不修改那里的方块。

沿用2.0.10增加的独立`lanshiyi:grave_vault_anchor`原生常加载锚点，带`minecraft:tick_world`、`radius=2`、`never_despawn=true`。所有墓碑共用同一个锚点；锚点不持有遗物，不为每座墓碑单独创建。保险库无碰撞、无重力、无可交互容器UI，包含持久化、防火与全伤害拦截组件，不依赖物品JSON重建附魔等数据。

**2.0.11根因修复：** 官方Windows BDS 1.26.63.1解析旧实体定义时，报告`deals_damage`只接受字符串；旧布尔值`false`被拒绝，地下库存和锚点约100tick后因`suffocation`死亡。现在四类保护实体统一使用无条件触发器`{"deals_damage":"no"}`，覆盖窒息等伤害。持久化组件不会阻止死亡，无碰撞/无重力也不等于免疫窒息。掉落实体浮力同时由非法的1.2修正为允许范围内的1.0。

启动及每100tick重新核对锚点与实际区块状态，不再永久缓存“已就绪”。旧保险库未加载时，尝试预加载或重建名为`lanshiyi_grave_vault`的命令常加载区域作为恢复入口，再创建/恢复共享锚点。不会因为某条命令失败就拒绝访问已经加载的正确库存。

开墓先核对原生实体ID、实体类型、编号和库存组件。ID失效时，在已加载维度中依据墓碑编号查找唯一库存并回写关联；没有找到则等待最多80tick，不能把区块方块已就绪当作库存实体已就绪。多份同编号候选时停止并提示，避免猜测串绑。库存确实缺失时保留墓碑和经验记录，不创建空库存。

`lanshiyi:gravestone` 是带编号的搬运凭据，实际遗物仍在保险库。挖起和放置只改变世界形态，不复制遗物。开启时优先把物品加入开启者背包，剩余部分保留在库存实体。已有钥匙、寻墓器和可搬运墓碑在死亡时保留在玩家身上，不形成墓碑套墓碑。

2.0.12起，普通绑定钥匙在**全部遗物领取完成**后消耗。异步库存加载结束后记录并验证当前使用槽位，仅扣该槽位中匹配本墓碑的1把普通钥匙；不扫描或删除其他槽位/玩家中的钥匙。满背包、部分领取、错误钥匙、加载失败及等待时切换钥匙均不提前扣除，腾出空间继续领取，经验仍只结算一次。空墓碑成功完成也消耗钥匙，传送次数用尽不影响开墓及消耗。管理员钥匙不消耗；使用管理员权限开启时不误删手持的其他墓碑钥匙。钥匙说明与基本信息同步展示此规则，旧版已有绑定钥匙直接适用。

`lanshiyi:grave_drop` 是带1格物品库存的独立实体，不是 `minecraft:item`。不含计时消失组件，包含 `minecraft:persistent`、`minecraft:fire_immune`、全伤害拦截和液体浮力；脚本另将岩浆内实体托至液面上方。拾取延迟约1.2秒，附近有背包空间的玩家自动拾取，实体才被正常移除。再次丢弃原生墓碑物品时，转换回同种持久实体。

清理 `@e[type=item]` 的常见掉落物命令不会匹配这种实体。管理员显式移除自定义实体、删除包、删除世界动态数据、编辑存档或其他模组主动删除这些实体，不在普通掉落保护能力范围内。

## 经验

在 `keepInventory=true` 的死亡处理期间获取 `player.getTotalXp()`，保存到记录后清零玩家经验，不额外生成经验球。首次成功开启并访问保险库时设置结算标志，发放 `floor(totalXp × 70 / 100)` 或 `floor(totalXp × 50 / 100)`。满背包重复打开不会重复发放。原版已经散落的经验无法从旧实体恢复，迁移记录经验为0。

## 传送

1. 表单显示时先依据持久化记录检查，**不要求区块已加载**。
2. 确认后重查玩家当前手持钥匙令牌，并锁定墓碑。
3. 使用`ls_tp_<编号>`临时常加载区域覆盖原位置水平±32格（通常5×5区块），最多等待80tick。命令失败但目标已加载时仍可在已加载范围寻找落点，不把已加载目标误报为丢失。
4. 方块就绪后额外等待墓碑显示实体最多80tick，每2tick检查一次；仅接受原维度、原位置附近、正确实体类型且编号匹配的实体。保存的实体ID失效时，按位置和编号恢复唯一关联并持久化；出现多个同编号候选则取消，不创建替代实体。等待期间保持临时区域和墓碑锁，后续再次验证手持钥匙、传送资格和目标方块；超时不扣费且释放区域与锁。

   核对仍在原始位置、未挖起、方块类型及对应编号显示实体；优先搜索水平8格/上下8格，再扩展到水平32格/上下32格。允许无碰撞草丛，避开岩浆、火、岩浆块等危险方块。按批次让出tick，避免长时间阻塞脚本。
5. **稳定API 2.0不存在`Block.isSolid`。** 原先读取此属性永远不能证明地面安全。现使用`getBlockFromRay`的原生碰撞检测（排除液体/可穿透方块），确认脚下实际支撑。
6. 没有天然落点时，在原位置附近向上寻找能容纳玩家和3×3圆石台的空旷空间。只用台面替换空气/液体，不破坏已有实心地形或墓碑。确认界面提前说明；成功后平台保留。
7. 异步搜索完成再次核对玩家、手持钥匙、墓碑状态和原位置方块；合计扣1颗末影珍珠，持久化令牌，再建台（如有）并调用`tryTeleport(checkForBlocks:true)`。
8. 失败时回退本次平台改动、恢复令牌并退珍珠；成功保留钥匙，刷新次数为0。整个加载范围没有可用空间或未就绪时仍明确提示、不扣费，不强行传入实心方块。
9. 无论结果如何释放临时区域和锁；世界重新启动时清理可能遗留的临时区域。

每把新钥匙分配 `lanshiyi:key_sequence` 生成的独立令牌，世界属性 `lanshiyi:k:<令牌>` 记录已用状态。相同钥匙被创造模式复制，副本仍共用一次传送资格。补发的新钥匙有新令牌，但不能绕过墓碑已移动的限制。

## 寻墓器与追踪边界

寻墓器使用16种同功能物品及对应针尖图标，脚本按玩家朝向选择帧，复制全部动态属性。菜单合成精确消耗当前手持绑定钥匙和一个指南针，避免工作台配方无法继承动态数据造成串绑。

- 玩家背包及副手：每5tick更新墓碑位置，先完成所有玩家位置扫描再刷新寻墓器，避免玩家枚举顺序造成延迟。
- 地面实体、墓碑显示实体、载具/生物库存：每20tick扫描已加载实体；移动目标存在最多约1秒更新延迟。
- 容器：玩家打开容器时登记并持久保存位置；追踪已登记容器及相邻连接容器，包括漏斗。每轮最多处理256个候选位置以控制开销。
- 未加载区块及离线持有者：位置停止变化，显示最后保存位置，不强制加载整个世界进行扫描。
- 跨维度：显示目标维度和坐标；玩家进入同维度后恢复真实水平针尖方向，不伪造跨维度空间向量。
- 已开启：保留最后记录，显示“已开启”。

任意管理命令把物品直接放进从未登记、不可达的容器，或非常长的自动化管线在扫描间隔内转移出已知范围时，稳定API没有覆盖所有容器槽位变化的通用事件；此时先显示最后记录位置，玩家打开目标容器后恢复追踪。**不把这类无法观测的位置变化承诺为无条件实时定位。**

## 升级

保留原包命名空间、9种模型及两个header UUID；当前版本2.0.14，以保留动态属性所属包身份。原版2.0.8的 `entity:grave_inventory` 保留42格库存结构，去除原来环境传感器的自动还原方块/掉物命令。旧实体加载时搬迁库存、分配编号、保留原始所有者标签；旧钥匙必须由所有者对正确旧墓碑使用并匹配原有维度/坐标，才能升级绑定。

2.0.9/2.0.10/2.0.11记录直接沿用；缺少`storagePosition`时回退到世界保存的保险库坐标，原实体ID不可用时依据编号恢复。已有墓碑/钥匙不统一重编号。旧版因窒息死亡的库存实体，以及已被覆盖或被外部移除的原生物品库存，无法仅凭编号和统计重建；需要出问题之前的世界备份。此次修复不会伪造空库存替换丢失遗物。

升级前备份世界；存有未领取遗物时不应直接降级回原始脚本，因为原版不认识保险库与新状态。
