# 墓碑模组 2.0.16

本版本修正远距离钥匙传送反复提示“目标区块尚未加载或常加载区域配额不足”的问题。主世界、下界、末地按原始墓碑坐标加载，不设置距离阈值，不进行下界8倍坐标换算。原有绑定钥匙直接适用，不需要重新死亡或补领。

## 变化

- 保险库共享原生锚点就绪后，回收冗余的`lanshiyi_grave_vault`命令区域，不再长期占用额外名额。
- 重试先清理同编号墓碑的残留临时区域，等待2tick让原生释放生效，再重新申请；不删除其他墓碑、管理员或其他模组的区域。
- 目标区块等待由80tick延长至400tick（20TPS下约20秒），加载时显示进度提示；切换钥匙或玩家失效会及时取消并释放区域和锁。
- 完整搜索区域因边界等原因无法申请时，退回墓碑所在区块加载，在实际已加载范围内寻找安全点，不因扩展区域失败就直接拒绝有效目标。
- 继续单独等待显示实体，按原维度、原位置和编号重连失效ID；不把未加载当作墓碑丢失，不创建替代墓碑或空库存。
- 钥匙次数说明在传送前的有效库存事务内刷新，避免跨维度后旧句柄失效；失败回滚钥匙说明、次数、珍珠和本次平台改动。
- 扩展区域配额、异步释放、慢加载、取消、并发和三维度9种来源/目标组合的模拟回归；增加独立BDS双会话传送验收入口。

## 安装与兼容

下载`Gravestones-lanshiyi-v2.0.16.mcaddon`及同名`.sha256`，核对摘要，备份世界，再同时替换行为包和资源包。最低引擎1.21.90，稳定Script API 2.0.0；包UUID、编号、原生遗物、经验和已用钥匙令牌保持兼容。详见[安装指南](INSTALL.md)。

本版不改变“墓碑从未搬动、未开启、每把钥匙一次、成功扣1颗珍珠”的规则。远端加载仍需世界允许命令，每个同时传送至少有1个可用命令常加载名额。全部名额被其他区域占满、坐标超出引擎边界、墓碑被删除或附近没有容身空间时，安全取消并保留费用，不承诺越过引擎限制。诊断见[问题排查](TROUBLESHOOTING.md)。
