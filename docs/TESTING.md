## 原生引擎复现与回归

旧版2.0.10定义在BDS 1.26.63.1中报告：

```text
minecraft:damage_sensor | deals_damage | unknown child schema option type. Allowed types: 'string'
PROBE DIE {"type":"lanshiyi:grave_storage","cause":"suffocation"}
PROBE DIE {"type":"lanshiyi:grave_vault_anchor","cause":"suffocation"}
```

实际还发现稳定API 2.0的Block没有`isSolid`属性。原先JS模拟器错误提供了该属性，因此旧测试没有识别出传送缺陷。现删除模拟器的该属性，类型化方块访问，并改用引擎碰撞射线。

修复后的双会话测试会在全新的独立测试世界中：

1. 调用实际死亡捕获逻辑，生成编号1、2、3及三份原生库存，库存和锚点处在世界最低高度附近的实心岩层内。
2. 等待400tick，确认实体仍有效；随后正常停止BDS，写入世界。
3. 再次启动同一测试世界，确认三份库存重新加载。
4. 检查钻石数量、剑的锋利V、123耐久损耗、名称/说明、物品动态属性和头盔。
5. 填满开启者原生容器，先开启确认未领完、对应钥匙仍在，再腾空领取，确认遗物独立完整、经验只结算一次，全部领取后使用槽位中的普通钥匙被消耗。
6. 用真实方块验证向下6格草丛落点和3×3圆石平台的碰撞支撑。

上述库存使用42格原生实体容器作为玩家入口适配，**不是实际玩家36格背包或真实登录会话**。跨维度玩家传送、移动UI、真实死亡与其他模组并存仍需人工验收。模拟测试不能替代引擎测试，引擎适配测试也不能替代玩家实际操作。
